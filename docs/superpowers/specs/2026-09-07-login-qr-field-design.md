# 登录模块：二维码输入框

日期：2026-09-07

现状：`/login` 已有手机号 OTP，微信入口点开后只展示 mock 票据字符串。账号规格要求登录页**内嵌二维码**（`docs/superpowers/specs/2026-09-01-account-login-design.md` §3），而不是整页跳转。

本设计只改登录模块的扫码面，不改会话、BFF 契约、设备绑定。

Figma：[灾害预警 · 登录二维码输入框](https://www.figma.com/design/Y1k112CejokbNLMf8Hl9co)

可交互稿：`docs/design/login-qr-field.html`

## 1. 对象与一句话

- **产品**：灾害预警值班台。
- **谁来用**：要绑定 Bark 设备、接收地震/海啸/天气预警的人。
- **这一屏的工作**：选一种方式进入值班台。扫码是第二种登录方式，不是社交按钮下面的附录。

## 2. 方案比较

| | A. 卡片内分段：手机号 / 扫码（推荐） | B. 手机表单再加一行「二维码」 | C. 仍点微信，只把票据卡换成码 |
| --- | --- | --- | --- |
| 做法 | 登录卡片顶部用分段控件切换。扫码页只有一个「二维码」字段。点微信切到扫码段。 | 手机号、验证码下面再放二维码井。 | 社交区分隔线以下的交互不变，展开区换成码。 |
| 好处 | 两种登录动词分开：手机点「登录」，扫码对准即签入。字段语法（标签 / 提示 / 错误）与手机号一致。 | 改动面最小。 | 与当前信息架构最接近。 |
| 代价 | 要加分段控件。 | 一张表单里两个提交意图，页面过长。 | 扫码仍像附属功能，规格里的「内嵌码」不够显。 |

**采用 A。** 扫码不是第三行输入，是与手机号并列的方式。微信按钮的工作是「打开扫码段」，不再在表单下方再堆一张卡。

## 3. 视觉计划

沿用现网值班台，不另起一套登录皮肤。现网已经是 zinc / shadcn、系统中文黑体、右侧雷达圈；二维码必须长得像这套仪器，而不是微信绿码。

### 色

| 角色 | 值 | 用途 |
| --- | --- | --- |
| Paper | `--background` | 表单列 |
| Ink | `--foreground` | 码点、标题 |
| Rail | `--muted` | 右列、分段轨道 |
| Stroke | `--input` / `--border` | 字段边、准星 |
| Quiet | `--muted-foreground` | 提示、票据前缀 |
| Fault | `--destructive` | 过期、不可用 |

码点用 Ink，不用微信绿。微信身份已经由社交行按钮承担。

### 字

- 展示：现网 `login-headline`，28px / 600，字距 -0.03em。
- 正文：14px，系统黑体（`--font-sans`）。
- 读数：票据用 `--font-mono`，12px，像台站编号。

### 布局

```
[ 品牌 灾害预警          主题 ]
及时知情，及时避险
用手机号或微信登录后，再绑定设备的推送令牌。

┌ 卡片 ─────────────────────┐
│ [ 手机号 | 扫码 ]          │
│                            │
│ 二维码                     │
│ ┌ 输入井 ───────────────┐ │
│ │ ⌜  准星 + 码图   ⌝   │ │
│ │ ⌞  票据 [      ] ⌟   │ │
│ └──────────────────────┘ │
│ 打开微信对准此码。值班台会自动签入。 │
│ [ 模拟确认 ]  ← 仅 AUTH_MOCK │
└────────────────────────────┘
或者
[ 微信 ] [ 支付宝 ] [ Google ]
```

右列雷达圈保留。扫码段与雷达是同一套「对准」语言：左边是要扫的靶，右边是值班台氛围。

### 签名元素

**准星井。** 二维码不是悬浮卡片，是和手机号同级的字段：标签「二维码」，井的圆角、描边、聚焦环与 `Input` 相同。井内四角 L 形刻度呼应右列同心圆。开发模式下，井底是一条票据读数带（前缀「票据」+ 粘贴框），不是第二张卡。

这是本页唯一的冒险：拒绝微信绿、拒绝把票据字符串当正文。其余克制，沿用现网控件。

## 4. 字段解剖

`QrField` 是一个表单控件，不是弹层。

| 零件 | 生产 | `AUTH_MOCK=true` |
| --- | --- | --- |
| 标签 | 二维码 | 同左 |
| 码图 | WxLogin 码，25×25 模块视觉，200px 井 | 由 `ticketId` 生成可扫的 mock 码 |
| 准星 | 四角 L | 同左 |
| 读数带 | 无 | `票据` + 可粘贴输入 + 刷新 |
| 主按钮 | 无（扫完自动签入） | 「模拟确认」，文案与现网一致 |
| 提示 | 打开微信对准此码。值班台会自动签入。 | 打开微信对准此码，或粘贴开发票据。 |
| 社交行 | 微信切到扫码段；支付宝 / Google 仍禁用 | 同左 |

### 状态

| 状态 | 井内 | 提示 / 错误槽 |
| --- | --- | --- |
| 生成中 | 骨架脉冲，准星仍在 | 正在生成二维码 |
| 就绪 | 码图清晰 | 默认提示 |
| 过期 | 码图降低对比，中央「已过期」+「刷新」 | 二维码已过期，点刷新 |
| 不可用 | 空井，短句 | 扫码暂不可用，请用手机号登录 |
| 校验失败 | 保持就绪码（可再扫） | 扫码确认失败 / 二维码已过期，请刷新 |

错误槽语法与 `Field` 相同：`role="alert"`，预留高度，避免布局跳动。

聚焦：井领取与输入框相同的 `focus-visible` 环。键盘可到刷新、模拟确认、微信按钮。`prefers-reduced-motion: reduce` 时关掉脉冲和码图切换动画。

## 5. 交互

1. 默认停在「手机号」。手机号 / 验证码 / 登录按钮现网行为不变。
2. 点「扫码」或「微信」：切到扫码段，请求（或复用）票据，生成中 → 就绪。
3. 生产：微信回调 `code` 后 BFF 写 cookie，前端进 `/devices`。过期只刷新码，不建半截用户。
4. Mock：可扫 mock 码，也可把 `ticketId` 贴进读数带，再点「模拟确认」。`POST /api/auth/mock/wechat/confirm` 不变。
5. 支付宝 / Google 仍禁用，文案不变。
6. 不再在社交行下方展开第二张「微信扫一扫（开发）」卡。

## 6. 文案

| 位置 | 文案 |
| --- | --- |
| 分段 | 手机号 / 扫码 |
| 标签 | 二维码 |
| 就绪提示 | 打开微信对准此码。值班台会自动签入。 |
| Mock 提示 | 打开微信对准此码，或粘贴开发票据。 |
| 读数前缀 | 票据 |
| 读数占位 | 粘贴开发票据 |
| 刷新 | 刷新 |
| Mock 按钮 | 模拟确认 |
| 生成中 | 正在生成二维码 |
| 过期覆盖 | 已过期 |
| 过期错误 | 二维码已过期，点刷新 |
| 不可用 | 扫码暂不可用，请用手机号登录 |

不写「请使用微信扫一扫登录本站」这类套话。不把 `ticketId` 当段落正文展示。

## 7. 不做

- 不改 OTP、session cookie、设备绑定。
- 不把微信绿、微信 logo 大图放进码井。
- 不解析图片上传来「识别二维码」。
- 不在手机号表单里塞第三行文本框当「二维码输入」。
- 不整页跳转到开放平台。

## 8. 实现落点（本设计通过后再做）

- `LoginPage`：分段控件；微信 `onSelect` 切到扫码段。
- 新控件 `QrField`：井、准星、码图、读数带、状态。
- `ds.css`：`.qr-field` / `.qr-reticle` / `.qr-readout`，颜色只引用现网 token。
- 测：切到扫码出现二维码字段；mock 粘贴票据后「模拟确认」仍走现网 confirm；手机号段回归；过期与不可用文案。
