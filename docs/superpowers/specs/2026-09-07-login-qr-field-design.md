# 登录模块：图形验证码门闩短信

日期：2026-09-07（再更正）

发送短信验证码之前，必须先看图、填 6 位数字。图形验证码正确，才发手机短信。扫码界面先保留。

可交互稿：`docs/design/login-qr-field.html`（默认手机号段）

## 1. 对象与一句话

- **产品**：灾害预警值班台。
- **谁来用**：用大陆手机号进值班台的人。
- **这一屏的工作**：读图上的 6 位读数并抄进格子；抄对了才能把短信打到手机上；再填短信码登录。

现网 `POST /api/auth/phone-number/send-otp` 只收 `phoneNumber`，没有图形校验。本设计要加门闩。网页仓库目前没有 captcha 接口。

## 2. 流程

```
手机号 → 读图形验证码 → 填 6 位 → 发送验证码
                ↓ 错
           换图、清空格子、提示不正确
                ↓ 对
           发短信、开始 60s 冷却
短信码 → 登录
```

点「发送验证码」时一并校验图形码，不另做「确认图形」按钮。

| 条件 | 行为 |
| --- | --- |
| 手机号不是 11 位大陆号 | 不发短信，错误写在手机号槽 |
| 图形码不足 6 位 | 不发短信，「请输入图形验证码」 |
| 图形码与图不一致 | 不发短信，「图形验证码不正确」，换一张，清空六格 |
| 图形码正确 | 才请求发短信；成功则「短信验证码已发送」并倒计时 |
| 登录时短信码空 | 「请输入短信验证码」 |

## 3. 方案比较

| | A. 图在上、六格在下，短信仍单行（推荐） | B. 图和输入左右并排 | C. 两个六格井 |
| --- | --- | --- | --- |
| 做法 | 图形是一条全宽「记录纸」。六格井专门抄这 6 个数字。短信验证码保持现网单行 + 发送。 | 左图右输入，常见门户布局。 | 图形和短信都用六格。 |
| 好处 | 抄图是唯一放大的动作；短信自动填充不会灌进图形格（图形 `autocomplete=off`）。 | 更省纵向空间。 | 两套码外形一致。 |
| 代价 | 卡片略高。 | 420px 卡片里图会被压得难认。 | 两个井分不清该填哪一个。 |

**采用 A。** 扫码段不改。

## 4. 视觉计划

沿用现网 zinc / 系统黑体。图形验证码不要做成彩虹噪点、斜杠、微信绿。

### 色

| 角色 | 值 | 用途 |
| --- | --- | --- |
| Paper | `--background` | 表单、六格井 |
| Rail | `--muted` | 图形条底 |
| Ink | `--foreground` | 图上数字、格子数字 |
| Stroke | `--input` / `--border` | 井边、格线、图上网格 |
| Quiet | `--muted-foreground` | 换一张、空格短横 |
| Fault | `--destructive` | 图形错、短信空 |

### 字

- 标题：现网 28px / 600。
- 标签：13px / 600。
- 图形数字与格子：`--font-mono`，图上约 22px 微倾，格子 20px 等宽。

### 布局

```
[ 品牌 灾害预警          主题 ]
及时知情，及时避险

┌ 卡片 ─────────────────────────┐
│ [ 手机号 | 扫码 ]               │
│                                │
│ 手机号                         │
│ [+86][                    ]    │
│                                │
│ 图形验证码              换一张  │
│ ┌ 记录纸 / 6 位数字 ────────┐  │
│ └──────────────────────────┘  │
│ ┌──┬──┬──┬──┬──┬──┐          │
│ │  │  │  │  │  │  │          │
│ └──┴──┴──┴──┴──┴──┘          │
│                                │
│ 短信验证码            发送验证码 │
│ [ 6 位短信验证码           ]   │
│                                │
│ [           登录           ]   │
└────────────────────────────────┘
```

### 签名元素

**记录纸。** 图形验证码是一条值班台记录纸：底是 `--muted`，上面有细网格和一道波形，6 个等宽数字轻微错位，像从监测卷纸上读站号。人把读数抄进下面的六格井。这是本页唯一放大的东西。

不采用：彩噪验证码、汉字点选、左右并排小图。

## 5. 字段

| 字段 | 控件 | 自动填充 |
| --- | --- | --- |
| 手机号 | 现网 `PhoneInput` | `tel-national` |
| 图形验证码 | 记录纸 + 六格井 + 换一张 | `autocomplete=off`，`inputMode=numeric`，6 位数字 |
| 短信验证码 | 现网单行输入 | `one-time-code` |
| 发送验证码 | 短信标签右侧文字按钮 | 先过图形门闩再发 |

换一张：新挑战、清空六格、清图形错误。冷却期间也可换图，但不重置短信倒计时。

### 状态（图形）

| 状态 | 记录纸 / 井 | 提示 |
| --- | --- | --- |
| 默认 | 新图，六格空 | 预留空槽 |
| 输入中 | 格子逐位亮 | 空 |
| 不正确 | 井边 Fault，立刻换图 | 图形验证码不正确 |
| 通过 | 井恢复描边 | 短信验证码已发送（写在短信槽） |

## 6. 扫码（先保留）

扫码段、微信入口、准星井、mock 票据，维持上一版。默认打开手机号段。

## 7. 文案

| 位置 | 文案 |
| --- | --- |
| 图形标签 | 图形验证码 |
| 换图 | 换一张 |
| 图形空 | 请输入图形验证码 |
| 图形错 | 图形验证码不正确 |
| 短信标签 | 短信验证码 |
| 发送 | 发送验证码 / 发送中 / Ns |
| 已发 | 短信验证码已发送 |
| 短信空 | 请输入短信验证码 |
| 手机号非法 | 请输入 11 位大陆手机号 |

## 8. 契约缺口（实现时）

BFF 今天没有图形验证码。建议：

- `GET /api/auth/captcha` → `{ challengeId, image }`（svg 或 png）
- `POST /api/auth/phone-number/send-otp` 增加 `{ phoneNumber, challengeId, captcha }`
- 挑战一次性；失败或换图都作废旧 id
- `AUTH_MOCK=true` 时图上仍是可读 6 位数字，便于人工测；生产用同等 6 位数字图，不要改成汉字点选

短信 verify 仍是 `{ phoneNumber, code }`。

## 9. 不做

- 本轮不改 `LoginPage` 生产代码，先定稿。
- 不删扫码段。
- 图形和短信不做成两套六格井。
- 不用滑块、点选汉字、邮件码。
