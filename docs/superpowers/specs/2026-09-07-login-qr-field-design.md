# 登录模块：图形验证码弹层

日期：2026-09-08

发送短信前必须过图形验证码。校验改到**弹层**里做，主表单保持短；弹层按移动端先设计。扫码界面先保留。

可交互稿：`docs/design/login-qr-field.html`（工具条可切「手机预览」）

## 1. 对象与一句话

- **产品**：灾害预警值班台。
- **谁来用**：手机上用大陆号登录的人居多，桌面也能用。
- **这一屏的工作**：主表单只办登录；点发送后弹出一张「读数条」，抄对 6 位才把短信发出去。

现网 `send-otp` 仍只有 `phoneNumber`。网页没有 captcha 接口。

## 2. 为什么用弹层

内联图形码会把登录卡拉得很长，窄屏还要和键盘抢高度。弹层的好处：

- 主路径仍是：手机号 → 短信码 → 登录。
- 图形校验是一次打断，做完即关。
- 窄屏用底栏，键盘顶起来时格子仍在拇指区；宽屏用居中小卡片。

点「发送验证码」时：手机号合法才打开弹层。弹层里点「确认并发送」（或填满 6 位后自动校验）。不对则留在弹层里换图；对了才关层、发短信、倒计时。

## 3. 方案比较

| | A. 窄屏底栏 / 宽屏居中卡（推荐） | B. 永远居中 Dialog | C. 图形仍内联在表单 |
| --- | --- | --- | --- |
| 做法 | `<640px` 和手机预览：从底部滑出，顶圆角，底部 `safe-area`。更宽：居中卡片，沿用现网 `Dialog`。 | 各宽度都 `top/left 50%`。 | 上一版。 |
| 好处 | 键盘弹出时底栏跟着 visual viewport；主表单短。 | 实现最接近现成 Dialog。 | 少一次点击。 |
| 代价 | 两套定位。 | 手机上弹层会被键盘挡住或挤到屏幕外。 | 窄屏一屏放不下。 |

**采用 A。** 实现时桌面用现网 `Dialog`；窄屏给 `DialogContent` 加底栏定位类，不要另做一套组件库。

不采用：全屏接管、滑块、点选汉字。

## 4. 流程

```
手机号合法 → 点「发送验证码」→ 弹出读数条
                ↓ 取消 / 点遮罩
           不发短信，主表单不变
                ↓ 6 位错误
           「图形验证码不正确」，换图，清空格子，弹层不关
                ↓ 6 位正确
           关弹层，发短信，60s 冷却，短信槽提示已发送
短信码 → 登录
```

冷却中再点「发送验证码」不打开弹层。冷却结束换图再发。

| 条件 | 行为 |
| --- | --- |
| 手机号不是 11 位大陆号 | 不打开弹层，错误写在手机号槽 |
| 弹层里不足 6 位还点确认 | 「请输入图形验证码」 |
| 与图不一致 | 「图形验证码不正确」，换一张，清空六格 |
| 一致 | 关层并发短信 |
| 登录时尚未发出短信 | 「请先发送短信验证码」 |
| 登录时短信码空 | 「请输入短信验证码」 |

## 5. 视觉计划

沿用 zinc / 系统黑体。弹层不是 iOS 毛玻璃，是值班台的一张读数条。

### 色 / 字

与上一版相同：Paper、Rail、Ink、Stroke、Quiet、Fault。图上数字与六格用 `--font-mono`。

### 主表单（短）

```
┌ 卡片 ─────────────────────────┐
│ [ 手机号 | 扫码 ]               │
│ 手机号                         │
│ [+86][                    ]    │
│ 短信验证码            发送验证码 │
│ [ 6 位短信验证码           ]   │
│ 短信验证码已发送                │
│                                │
│ [           登录           ]   │
└────────────────────────────────┘
```

「发送验证码」与标签「短信验证码」同一行、右对齐。提示「短信验证码已发送」和登录按钮之间至少再留 24px，不要贴着。

### 弹层（窄屏底栏）

```
████ 遮罩 ████████████████████
┌──────────── ▬ ────────────┐
│ 图形验证码                 │
│ 看图输入 6 位数字…  换一张 │
│ ┌ 记录纸 ────────────────┐ │
│ └────────────────────────┘ │
│ ┌──┬──┬──┬──┬──┬──┐      │
│ └──┴──┴──┴──┴──┴──┘      │
│ 提示槽                     │
│ [      确认并发送      ]   │
│ 取消                       │
└────────────────────────────┘
  safe-area
```

「换一张」与说明「看图输入 6 位数字，正确后发送短信」同一行、右对齐。标题单独一行。

宽屏：同一内容放进居中卡，最大宽 400px，没有顶栏拖条，遮罩点击关闭。

### 签名元素

**记录纸仍在弹层里。** 底栏只是容器；真正被记住的是那条网格+波形的 6 位读数。顶上 36×4px 横条只出现在底栏，表示「从下面抽出」，不是装饰。

## 6. 移动端约束

- 底栏 `padding-bottom: max(16px, env(safe-area-inset-bottom))`。
- `max-height: 92dvh`，内容不滚动（记录纸 + 六格 + 按钮刚好一屏）。
- 打开后聚焦六格隐藏 input，`inputMode=numeric`，`autocomplete=off`（不要抢短信自动填充）。
- 短信输入仍在主表单，`autocomplete=one-time-code`。
- 键盘顶起时：底栏用 `bottom: 0` 贴 visual viewport，不要用 `top: 50%`。
- 主按钮全宽 44px 高，方便拇指。
- 「取消」是按钮，不只靠小叉。遮罩点击 = 取消。
- `prefers-reduced-motion: reduce` 时底栏不滑入，直接出现。
- 窄屏社交行已是单列；手机预览隐藏右列雷达。

## 8. 技术契约

视觉已定稿。实现以 [2026-09-08-login-captcha-tech.md](./2026-09-08-login-captcha-tech.md) 为准。

图形码由 [mango-captcha](https://github.com/luyi2008/mango-captcha) 边缘函数签发并校验。浏览器打 `GET /api/code` 与 `POST /api/send-code`；源站 BFF 只信 `X-ESA-Assertion`。公网 `send-otp` 关掉。

- 不删扫码段。
